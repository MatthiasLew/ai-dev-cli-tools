Base revision: `5db26b7aac599eca7c67407904f80909ceacaa09` (1.2.2).

## Scope and assessment

Repository-wide inventory and static checks covered all 90 runtime Python modules, the test suite,
scripts, packaging configuration and workflows. Manual review concentrated on execution and test
selection, parsers, context selection/budgeting/serialization, progressive evidence, cache keys,
finish readiness, subprocess lifecycle, local MCP boundaries, masking, and release gates.
This is a maintenance audit with targeted manual review, not a claim that every line or every
supported platform was independently verified.

The toolkit already has a substantial capability set. The main priority is trustworthy evidence:
a selected test must actually execute, a selected file must deliver usable source, and report-size
claims must describe what the agent receives. Adding more broad commands is lower value than
strengthening these existing contracts.

## Context contract and compatibility

`max_chars` now explicitly means emitted source/diff content characters. Full report metadata is
outside this limit and can make the complete JSON/Markdown substantially larger. The report exposes
`scope`, actual artifact `json_chars`/`markdown_chars`, and `metadata_overhead_chars`. It does not
claim a hard cap on transport payloads or measured provider-token savings. CLI pretty printing and
MCP envelopes have additional overhead. Diagnostics use serialized JSON size rather than mistaking
content size for total delivery size.

Truncated entries retain evidence IDs and concrete expansion commands. Selection receipts expose
both `list_truncated` and `content_truncated`. Markdown places source before detailed metadata.
See [the context contract](CONTEXT_BUILDER.md). Existing consumers treating `used_chars` as whole
report size should switch to the serialized-size fields.

## Validation

- Full pytest suite: 530 passed, 6 skipped. The six skips are opt-in external toolchain cases.
- Real toolchain smoke explicitly enabled for Python and Node: 2 passed, 4 unrequested families skipped.
- Ruff, strict mypy over source/tests/scripts, coverage gate >=90%, CI configuration validation,
  distribution build and installed-wheel smoke are the required local gates.
- The installed-wheel smoke builds a real wheel and invokes its installed entrypoint in a clean
  virtual environment; it does not substitute an editable-source test.
- New regressions additionally exercise cancellation, timeout and large subprocess output.
- Linux was executed locally. Windows/macOS and the full Python-version matrix remain CI evidence;
  local success alone does not establish those results. No PyPI release was requested or published.

## Recommended follow-up work

1. **Cache environment identity (high priority).** Validation keys include repository content,
   command, workspace, OS, architecture and Python version, but do not fingerprint the actual Node,
   Java, PHP or compiler binary versions, installed dependency state, or relevant environment values.
   Extend keys with explicit toolchain fingerprints and opt-in environment inputs. Until then use
   `--no-cache` after environment/toolchain changes. Avoid collecting or storing secret values.
2. **Independent total-delivery budget (medium priority).** Add a separate bounded transport mode
   with concise metadata and expandable evidence. Do not silently reinterpret the documented content
   budget again. Benchmark the full serialized response and whether the agent has sufficient code.
3. **Godot adapter (medium priority).** Detect `project.godot`, report GDScript, and suggest a configured
   local validator. Keep automatic execution consistent with existing execution policy. Include a
   small synthetic project in the regression corpus rather than using private game code.
4. **Cache concurrent writers (medium priority).** Validation-cache writes currently share a `.tmp`
   filename for a given key. Use unique temporary files and test simultaneous identical check runs
   before advertising multi-process cache writes as reliable.
5. **Broader runner-output corpus (medium priority).** Add versioned Node spec/TAP samples, cancelled
   tests, mixed-language projects and unknown extensions. Prefer concrete failing fixtures to adding
   another general-purpose command.
